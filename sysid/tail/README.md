# System Identification & Benchmarking Guide for Soft Fish

This directory contains the entire suite for systematically characterizing the physical limits, kinematics, and hydrodynamics of the soft robotic fish. This process is mandatory before introducing Reinforcement Learning (RL).

## Directory Structure
- `data/`: All raw CSV files generated by the experiments are saved here.
- `plots/`: All generated analysis graphs (stiffness curves, Bode plots) are saved here.
- `calibrate_stiffness.py`: The Phase 1 static calibration script.
- `plot_stiffness.py`: Generates the stiffness/hysteresis curve.
- `run_dynamic_benchmark.py`: The Phase 2 & 3 automated grid-search script (runs all frequency/amplitude combos).
- `analyze_dynamic_benchmark.py`: Generates the Bode plots, Torque Heatmaps, and Speed analysis.
- `vibration_benchmark.py`: Synchronously logs IMU data while running motor sine waves to measure dynamic noise.

---

## NEW WORKFLOW: Spooled Tendon Length (Arclength) Focus
Instead of dealing with raw Dynamixel ticks, the entire pipeline is now generalized to **spooled tendon length** (in mm). You must specify your pulley's radius during these phases. The scripts will automatically convert between tendon travel and motor ticks. This allows easy swapping of pulleys and prevents overwriting data by using `--dataset` flags.

---

## PHASE 1: Safe Kinematic Mapping (In Air)
**Goal:** Define the absolute safe physical boundary ($Travel_{max}$ in mm) for position control and eliminate tendon creep/slack.

### Execution Steps:
1. Ensure the fish is out of the water, hanging freely.
2. Run the calibration script at a low maximum current (e.g., 300mA) and specific pulley radius to check for snags. Use `--dataset` to label your test runs easily.
   ```bash
   python calibrate_stiffness.py --max_current 300 --pulley_radius 12.5 --dataset my_fish_v1
   ```
3. Plot the result to check for stick-slip/friction (the flat deadzones):
   ```bash
   python plot_stiffness.py --file YOUR_FILE_NAME.csv
   ```
4. If the tendon stretched (crept), physically re-tighten it to remove the slack.
5. Step up the maximum current until the tail bends to your **desired absolute maximum angle**:
   ```bash
   python calibrate_stiffness.py --max_current 600 --pulley_radius 12.5 --dataset my_fish_v1
   ```
6. **Look at the plot or terminal output.** Note the highest `Tendon Pull: [X] mm` value. This is your maximum safe tendon travel boundary.
7. **Write this value down.** You will use it as `--max_tendon_travel` for Phase 2.

---

## PHASE 2: Dynamic Bandwidth Benchmarking (In Air)
**Goal:** Map the frequency response and identify the motor's speed/acceleration saturation limits without water drag.

### Execution Steps:
1. Run the automated grid search. Pass the max travel boundary found in Phase 1. This will automatically run a matrix of tests (1Hz to 4Hz, 20% to 100% amplitude) and save the files into the `data/` folder.
   ```bash
   python run_dynamic_benchmark.py --env air --pulley_radius 12.5 --max_tendon_travel 15.0 --dataset my_fish_v1
   ```
2. Analyze the results to generate the Bode plots, Torque Heatmaps, and the Speed Saturation plots.
   ```bash
   python analyze_dynamic_benchmark.py --env air --dataset my_fish_v1
   ```

---

## PHASE 3: Hydrodynamic Benchmarking (In Water - Tethered)
**Goal:** Quantify the "Added Mass" and "Hydrodynamic Drag" of the water to see how it restricts your frequency and torque limits.

### Execution Steps:
1. Submerge the fish in the testing tank. Rigidly mount the head so it cannot swim forward (stationary swimming).
2. Run the exact same automated grid search, but label it as water.
   ```bash
   python run_dynamic_benchmark.py --env water --pulley_radius 12.5 --max_tendon_travel 15.0 --dataset my_fish_v1
   ```
3. Analyze the results to compare the water runs against the air runs.
   ```bash
   python analyze_dynamic_benchmark.py --env water --dataset my_fish_v1
   ```

---

## PHASE 4: Open-Loop Free-Swimming Test
**Goal:** Find the biological Strouhal number and maximum free-swimming speed before giving control to RL.

### Execution Steps:
1. Look at your Phase 3 (Water) analysis graphs. Identify the highest frequency that successfully tracked at least 70% of the commanded amplitude without the motor hitting the 1000mA ceiling and without hitting the speed saturation limit.
   * *Example: 3.0 Hz at 80% amplitude.*
2. Untether the fish in a large tank or pool.
3. Run a continuous sine wave using `fastPositionSineControl.py` (located in the main `softFish` folder) with those exact settings.
4. Record the fish on video with a ruler in the background. Calculate the forward velocity ($U$) in meters per second.
5. Calculate the Strouhal Number ($St = \frac{f \cdot A}{U}$). If $St$ is between 0.2 and 0.4, your mechanics are perfectly optimized for RL training!

---

## PHASE 5: IMU Dynamic Noise Benchmarking (For Kalman Filters)
**Goal:** Characterize the **Dynamic Mechanical Noise** of the motor vibrations. A Kalman Filter needs this specific measurement noise covariance ($R$ matrix) so it does not mistake motor vibrations for actual physical swimming movement.

### Execution Steps:
1. **Rigidly mount the fish:** Clamp the head/chassis to a heavy table (or rigidly mount it underwater). It must not be able to swing or move physically.
2. **Run the Vibration Benchmark:** Run the script using the exact frequency and amplitude you identified in Phase 4.
   ```bash
   python vibration_benchmark.py --max_tendon_travel 15.0 --freq 2.0 --amp_frac 1.0 --dataset my_vibration
   ```
   * *The script will ask you to calibrate the IMU by gently tilting it.*
   * *It will then give you a 30-second countdown to step away so you don't accidentally bump the table.*
   * *It will flap the tail violently for 30 seconds while logging the IMU data synchronously.*
3. **Analyze the Variance:** Fetch the data back to your laptop and run the IMU analyzer on it:
   ```bash
   # (Run on Laptop)
   cd ~/fishdeploy/imu
   python analyze_imu.py data/YOUR_VIBRATION_FILE.csv
   ```
4. **Update your Filter:** Look at the `Std` (Standard Deviation) values printed by the analyzer for the `Lin_Accel` and `Raw_Gyro` axes. Hardcode these values into your EKF's measurement noise matrix.
